# VYRN

## Подключение Supabase

В проект добавлены SQL-схема, Edge Function для Telegram-авторизации и клиентский API-адаптер. Telegram-запросы выполняются через `telegram-api` после проверки подписи `initData`. Обычный браузер может напрямую читать только разрешённые RLS-политикой публичные поля demo-профиля `telegram_id = 0`.

1. Создайте проект Supabase и откройте **SQL Editor**.
2. Выполните целиком `supabase/schema.sql` один раз.
3. Установите Supabase CLI, выполните `supabase login`, затем свяжите этот каталог с проектом командой `supabase link --project-ref <PROJECT_REF>`.
4. В настройках Telegram Mini App задайте HTTPS URL сайта. Для локального открытия HTML авторизация Telegram не работает.
5. Добавьте токен бота как секрет Edge Function, не помещая его в клиентский JavaScript:

	```powershell
	supabase secrets set TELEGRAM_BOT_TOKEN="<BOT_TOKEN>"
	```

	Supabase автоматически предоставляет Edge Function переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Для self-hosted среды, где service role key не предоставляется автоматически, задайте секрет `VYRN_SUPABASE_SERVICE_ROLE_KEY`. Ни один из этих ключей не добавляйте в клиентский JavaScript.
6. Разверните функцию из корня проекта:

	```powershell
	supabase functions deploy telegram-api --project-ref orcstihnyxrtgmvcbfiq --no-verify-jwt
	```

	Функция отключает проверку Supabase JWT на шлюзе, потому что вход подтверждается подписью Telegram `initData` внутри функции. Telegram bot token и service role key никогда не отправляются в браузер.
7. Укажите URL проекта и публичный `anon` key в `supabase-client-config.js`. В браузере разрешено хранить только публичный anon key; не вставляйте сюда service role key.

### Обычный браузер: просмотр профиля

В `supabase-client-config.js` включён `browserDemo: true`. В этом режиме клиент напрямую читает SQL views `browser_demo_profile` и `browser_demo_nfts`; последнее возвращает только NFT, которыми владеет профиль с `telegram_id = 0`. Edge Function для чтения не требуется. Выполните `supabase/browser-demo-read.sql` в Supabase SQL Editor после изменений этого файла. Повторный запуск обновит views и создаст кошельки с балансом `0`, не перезаписывая существующие балансы. Скрипт создаст тестовый профиль, только если его ещё нет. Anon получает доступ только к этим двум views, а исходные таблицы остаются закрытыми. До выполнения SQL REST API будет возвращать ошибку доступа или `404` для view.

Браузерный режим использует общий demo-профиль с `telegram_id = 0`. Через серверную функцию в нём доступны активация предназначенных для demo промокодов и анонимные номера; остальные игровые операции остаются доступны через Telegram. Не добавляйте общие права на изменение строки demo-профиля: anon key публичен.

Если браузер пишет о CORS preflight, сначала проверьте ответ Edge Function. `404` с текстом `Requested function was not found` означает, что функция не развёрнута в указанном проекте; это не ошибка CORS в браузерном коде. После deploy preflight `OPTIONS` должен возвращать `200` и заголовки `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods` и `Access-Control-Allow-Headers`.

После настройки Telegram-вход создаёт профиль, уникальный nickname формата `player` и шесть цифр, кошельки с нулевым начальным балансом и личный чат «Избранное». Профиль, коллекция NFT, рынок, диалоги и сообщения читаются и изменяются через Edge Function. Цены в `stars` хранят целые звёзды, а GRAM-балансы хранятся в минимальных единицах (`1 GRAM = 1 000 000 000` единиц).

При отправке личного сообщения бот отправляет адресату уведомление с ником отправителя. Чтобы Telegram разрешил боту написать пользователю, адресат должен заранее открыть бота VYRN и нажать «Запустить». Если Telegram не доставит уведомление, отправитель увидит предупреждение; само сообщение при этом останется в чате.

К уведомлению прикреплена кнопка «Открыть чат», которая запускает Mini App и открывает нужный диалог. Перед развёртыванием задайте секрет `VYRN_WEB_APP_URL` — HTTPS-адрес сайта или страницы чатов в развёрнутом приложении. Если указан адрес сайта (например, `https://example.com/vyrn/`), функция автоматически добавит `/chats.html`:

```powershell
supabase secrets set VYRN_WEB_APP_URL="https://example.com/vyrn/"
```

Замените пример на адрес сайта, настроенный для Telegram Mini App, и разрешите этот домен в настройках бота. После изменения URL или кода разверните обновлённую Edge Function `telegram-api` командой из шага 6.

### Локальный кэш разделов

Коллекция NFT, рынок, открытые профили и список диалогов кэшируются в браузерном `localStorage` по Telegram ID. При повторном открытии сохранённые данные отображаются сразу, а после истечения срока хранения обновляются с сервера в фоне. Успешные изменения данных очищают кэш пользователя. Баланс, платежи и сообщения не кэшируются; кэш служит только для быстрого отображения и не заменяет серверную проверку.

### Цвет баннера профиля

Обновите схему выполнением `supabase/profile-banner-colors.sql` в Supabase SQL Editor. Затем разверните обновлённую Edge Function `telegram-api`. Активный Premium или подтверждённый профиль может выбрать цвет баннера и включить градиент от верхнего края экрана на всю ширину, который плавно становится прозрачным у нижнего края блока имени и аватара. Право проверяется также на сервере, а цвет и настройка градиента сохраняются в профиле и доступны для отображения другим пользователям.

### Реферальная система

1. В BotFather задайте для `@vyrn_robot` основное Mini App (Main App), указывающее на опубликованный VYRN. Ссылка приглашения использует формат `https://t.me/vyrn_robot?startapp=<код>`.
2. В Supabase SQL Editor выполните `supabase/referrals.sql` после `supabase/schema.sql`.
3. Убедитесь, что в `supabase-client-config.js` указан правильный `botUsername`, затем разверните обновлённую Edge Function `telegram-api` и опубликуйте `profile.html`, `script.js`, `style.css`, `supabase-api.js` и `supabase-client-config.js`.

В настройках профиля игрок может скопировать или отправить персональную ссылку и посмотреть число приглашённых. Новый Telegram-профиль, впервые открытый по валидной ссылке, получает 5 Stars, пригласивший — 10 Stars. Награды начисляются сервером один раз при первом создании профиля; существующие профили и общий браузерный demo-профиль не участвуют. Параметр ссылки сверяется с подписанным Telegram `initData`, а бонусы и история кошелька записываются транзакционно.

### Оценка NFT в профиле

В профиле отображается суммарная оценка коллекции в Telegram Stars по ценам Fragment. Цены запрашиваются пакетами до 40 NFT; если Fragment не возвращает цену, показывается число NFT без оценки, а при наличии используется последняя сохранённая цена Fragment. Для получения свежих цен разверните обновлённую функцию `fragment-price`:

```powershell
supabase functions deploy fragment-price --project-ref orcstihnyxrtgmvcbfiq --no-verify-jwt
```

### Автопродажа NFT

После `supabase/schema.sql` выполните `supabase/auto-sell.sql` в Supabase SQL Editor и разверните обновлённую `telegram-api`. Кнопка автопродажи выкупает NFT по свежей оценке Fragment в Stars: комиссия составляет 30%, а для активного Premium — 10%. Чистая сумма зачисляется на Stars-баланс, NFT переходит в системный пул. Перед выкупом приложение получает свежую оценку Fragment, а сервер проверяет её актуальность и транзакционно применяет выкуп и зачисление.

### Макет ежедневных заданий

Страница `daily-tasks.html` доступна по ссылке «Перейти к заданиям» на главной. Макет показывает ежедневные и еженедельные задания с переключаемыми вкладками; прогресс и награды демонстрационные, выполнение пока не сохраняется.

## Важное для запуска

Каталог моделей NFT сам по себе не подтверждает владение. Чтобы у игрока появились реальные экземпляры, доверенный серверный импорт должен добавить строки в `nft_items` и назначить `owner_profile_id`; браузер не может выпускать NFT или назначать их себе. Рыночная покупка требует положительного баланса. Пополнение через Telegram Stars описано ниже; баланс меняется только после серверного подтверждения успешного платежа от Telegram.

Баланс аккаунта и профиль кэшируются в `sessionStorage` на 5 минут, поэтому при быстрых переходах между разделами баланс отображается сразу без повторной загрузки. После успешного изменения данных кэш очищается; страница кошелька обновляет его данными с сервера.

В личном чате нажмите ЛКМ или тапните по своему исходящему текстовому сообщению; нажатием ПКМ также можно открыть меню удаления. Удаление помечает сообщение удалённым на сервере для обоих участников; переписки обновляются автоматически.

## Пополнение через Telegram Stars

Курс пополнения: **1 VYRN Star = 1 Telegram Star (XTR)**. Оплата доступна только внутри Telegram Mini App; обычный браузер не может создать счёт или зачислить баланс.

1. В Supabase SQL Editor выполните `supabase/star-topups.sql` после `supabase/schema.sql`. Миграция создаёт таблицу платёжных намерений и ограниченные `service_role` RPC для проверки и однократного зачисления.
2. Убедитесь, что Edge Function secret `TELEGRAM_BOT_TOKEN` задан, как описано выше. Создайте секрет webhook и задайте его для функции. В PowerShell:

	```powershell
	$webhookSecret = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
	supabase secrets set TELEGRAM_WEBHOOK_SECRET="$webhookSecret" --project-ref orcstihnyxrtgmvcbfiq
	```

3. Разверните обновлённую Edge Function:

	```powershell
	supabase functions deploy telegram-api --project-ref orcstihnyxrtgmvcbfiq --no-verify-jwt
	```

4. Зарегистрируйте webhook Telegram на `https://orcstihnyxrtgmvcbfiq.supabase.co/functions/v1/telegram-api`, передав тот же `secret_token` и обновления `message` и `pre_checkout_query`. Например, вызовите Bot API `setWebhook` из защищённой административной среды с JSON:

	```json
	{
	  "url": "https://orcstihnyxrtgmvcbfiq.supabase.co/functions/v1/telegram-api",
	  "secret_token": "<тот же TELEGRAM_WEBHOOK_SECRET>",
	  "allowed_updates": ["message", "pre_checkout_query"]
	}
	```

	Запрос отправляется методом `POST` на `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook`. Не публикуйте URL с токеном бота и не добавляйте токен или webhook secret в файлы проекта. Если у бота уже настроен webhook для другого сервиса, `setWebhook` заменит его: сначала объедините обработчики или подготовьте отдельного бота.
5. Размещайте сайт по HTTPS и запускайте его как Telegram Mini App. Проверьте пробное пополнение: Telegram Stars спишутся при оплате, а VYRN Stars появятся после получения и проверки успешного webhook. Повторная доставка webhook не дублирует зачисление; в историю кошелька добавляется операция `telegram_stars_topup`.

Webhook проверяет `TELEGRAM_WEBHOOK_SECRET`, а перед выставлением счёта сервер проверяет подпись Telegram `initData`. Успешное зачисление дополнительно сверяет Telegram user ID, payload, XTR-сумму и уникальный charge ID. Никогда не начисляйте баланс по callback из браузера — он используется только для отображения статуса оплаты.

## Покупка VYRN Premium через Telegram Stars

Цены подписки: **99 XTR за 1 месяц, 890 XTR за 12 месяцев и 1 590 XTR за 24 месяца**. После получения `successful_payment` от Telegram сервер активирует Premium на выбранный срок. Callback в Mini App сам по себе не выдаёт Premium.

1. В Supabase SQL Editor повторно выполните обновлённый `supabase/premium-subscriptions.sql`, чтобы убрать тестовую цену из ограничений, закрыть старые неоплаченные тестовые счета и включить реальные тарифы. Если миграция ещё не применялась, выполните её после `supabase/schema.sql`. Оплаченную тестовую историю миграция сохраняет.
2. Разверните обновлённую Edge Function с реальными ценами:

	```powershell
	npx.cmd supabase@latest functions deploy telegram-api --project-ref orcstihnyxrtgmvcbfiq --no-verify-jwt
	```

3. Убедитесь, что webhook Telegram уже зарегистрирован с обновлениями `message` и `pre_checkout_query` и тем же `TELEGRAM_WEBHOOK_SECRET`.
4. Опубликуйте обновлённые файлы сайта. Откройте профиль внутри Telegram Mini App, выберите срок и проверьте сумму в счёте. Сервер самостоятельно задаёт цену для каждого срока; значения из клиентского запроса не используются как стоимость.

Оплаченный Premium хранится в `profiles.premium_until`. Повторная доставка одного webhook не продлевает подписку повторно; новый отдельный успешный платёж продлевает текущую подписку от её даты окончания.

Пока включены только срок Premium и бейдж профиля. Ежедневные Stars, смена баннера и скидка из списка преимуществ требуют отдельных игровых обработчиков и этой тестовой оплатой ещё не выдаются.



Капсулы, улучшения NFT, ежедневные задания и рейтинг на главной пока остаются макетными: для них нужны конкретные правила выпадения, стоимость операций, награды и формула рейтинга. Текущий серверный контур намеренно не начисляет случайные NFT или валюту.

## Админ-панель выдачи NFT

1. В Supabase SQL Editor выполните `supabase/admin-panel.sql` после основной схемы. После обновления SQL этого файла выполните его повторно, чтобы обновить функции админ-панели в Supabase, включая физическое удаление профиля игрока.
2. В `supabase/admin-set-password.sql` замените строку `REPLACE_WITH_A_LONG_RANDOM_ADMIN_PASSWORD` на уникальный пароль длиной от 20 символов и выполните этот SQL. Сам пароль не вставляйте в HTML/JS и не коммитьте этот SQL с заполненным паролем.
3. Опубликуйте `admin.html`, `admin.css` и `admin.js` вместе с остальными файлами на GitHub Pages и откройте `/admin.html`.
4. Введите пароль и найдите игрока по nickname, username, имени или Telegram ID. Для удаления выберите игрока, нажмите «Удалить игрока» и подтвердите действие вводом `УДАЛИТЬ <nickname>`. Операция безвозвратно удаляет профиль, его NFT, балансы, платежные записи и отправленные сообщения; общий браузерный demo-профиль защищён от удаления. Для выдачи подарка выберите коллекцию из списка либо укажите slug/название вручную, введите номер и проверьте предпросмотр и ссылку Fragment.

Цена выдачи загружается со страницы Fragment через Edge Function `fragment-price`: цена в GRAM делится на 10 и умножается на 80 Stars. В админ-панели её можно изменить вручную перед выдачей. Разверните функцию командой `supabase functions deploy fragment-price --project-ref <PROJECT_REF> --no-verify-jwt`.

Выдача создаёт/обновляет тестовое владение в таблицах VYRN и записывает передачу; она не передаёт реальный Telegram-подарок. Список панели включает все 120 коллекций, опубликованных в Fragment на момент последнего обновления кода. У Fragment нет используемого здесь официального открытого API поиска/выдачи: поиск по номеру формирует preview URL, а коллекцию, появившуюся позже, можно указать вручную по slug и проверить ссылкой на Fragment. Статус существования/владения номером Fragment нужно сверять на самом Fragment. Пароль проверяется в PostgreSQL через bcrypt, RPC-параметр передаётся по HTTPS и не сохраняется в браузере. Ограничьте доступ к ссылке панели и используйте длинный уникальный пароль.

## Ежедневные и еженедельные задания

1. Примените `supabase/admin-panel.sql`, если он ещё не установлен, и настройте пароль по шагам выше.
2. Выполните `supabase/daily-tasks.sql` в Supabase SQL Editor после основной схемы и SQL админ-панели. Повторный запуск безопасен: он обновит функции и добавит недостающие начальные задания.
3. Разверните функции из корня проекта:

	```powershell
	supabase functions deploy telegram-api --project-ref <PROJECT_REF> --no-verify-jwt
	supabase functions deploy admin-tasks --project-ref <PROJECT_REF> --no-verify-jwt
	```

4. Опубликуйте `daily-tasks.html`, `daily-tasks.css`, `daily-tasks.js`, `assets/svg/task.svg`, обновлённые `script.js` и `supabase-api.js`, а также `admin.html`, `admin.css` и `admin.js`.

В админ-панели можно установить от 1 до 100 заданий для каждого периода; начальные значения — три ежедневных и пять еженедельных. Выбирается случайное число заданий, не превышающее ни настройку, ни количество включённых заданий в соответствующем пуле; набор общий для всех игроков. Изменение количества применяется при следующем периоде, чтобы не менять уже выданный игрокам набор. Кнопка сброса досрочно обновляет текущие ежедневный и недельный списки для всех игроков, очищает их текущий прогресс и отметки полученных наград, но не списывает уже начисленные Stars. При наличии других заданий в пуле новый список старается не повторять предыдущий; если включённых заданий не больше заданного количества, список останется тем же. День меняется в 00:00 по Москве, неделя начинается в понедельник в 00:00 по Москве. Новые назначения создаются при первом запросе доски в соответствующем периоде; открытая страница обновляет список после возвращения в фокус и на границе периода. Удаление в админ-панели отключает задание, не затрагивая уже созданные назначения. Поддерживаются только события, доступные в форме админ-панели: посещения разделов, просмотр коллекции/NFT/лотов, сообщения, создание лота и покупка. Действия, для которых приложение пока не собирает события, нельзя использовать как автоматически проверяемые задания.

Выдачу за покупки не включайте в пул, если не хотите связывать награду с расходами игрока. Баланс начисляется серверной функцией только после проверки прогресса; повторная проверка не выдаёт награду второй раз.

2. Разверните обновлённую Edge Function `telegram-api` и опубликуйте `anon-numbers/anon-numbers.html`, `anon-numbers/anon-numbers.css`, `anon-numbers/anon-numbers.js`, `supabase-api.js`, `profile.html`, `script.js`, `style.css` и `index.html`.
3. Откройте раздел «Анонимные номера» в Telegram или браузере. В браузере номер сохраняется в общем demo-профиле с `telegram_id = 0`; баланс Stars также общий для посетителей demo-режима. Выбивание номера и каждое улучшение цифры стоят 25 Stars. Номер и его изменения сохраняются на сервере; улучшение обновляет существующую запись номера, не создавая новую.
4. В настройках профиля можно выбрать только один из собственных анонимных номеров. Установленный номер отображается под именем пользователя в профиле и может быть найден в чате по полному номеру `+888 XXXX XXXX`.

## Промокоды Stars и Premium

1. В Supabase SQL Editor выполните `supabase/promo-codes.sql` после основной схемы и `supabase/admin-panel.sql`.
2. Разверните Edge Functions из корня проекта:

	```powershell
	supabase functions deploy telegram-api --project-ref <PROJECT_REF> --no-verify-jwt
	supabase functions deploy admin-promocodes --project-ref <PROJECT_REF> --no-verify-jwt
	```

3. Опубликуйте обновлённые `wallet.html`, `script.js`, `supabase-api.js`, `style.css`, `admin.html`, `admin.js` и `admin.css`.
4. В `/admin.html` введите пароль администратора и создайте коды. Можно выпустить от 1 до 500 кодов за раз; награда составляет от 1 до 1 000 000 Stars либо от 1 до 12 месяцев Premium. Чтобы активировать коды без Telegram, отметьте «Только для браузерного demo-профиля»: они начисляются на общий demo-баланс, видимый всем посетителям сайта.
5. Сразу скопируйте или скачайте показанные коды: база хранит только их SHA-256-хеши, а сами коды отображаются в админке только после создания. Каждый код активируется один раз и становится недоступен всем остальным после успешного погашения. Demo-коды нельзя активировать через Telegram, а обычные коды — из браузерного demo-профиля.

Игрок активирует код в кошельке в Telegram или в браузерном demo-режиме, если код выпущен специально для demo-профиля. Stars начисляются в транзакции вместе с записью в истории операций; Premium продлевается от текущего срока действия. Повторные и слишком частые попытки отклоняются сервером.
